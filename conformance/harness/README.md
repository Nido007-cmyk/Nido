# NIDO Conformance Harness (language-agnostic)

The official vectors live in `../vectors/v0/final/*.json` (plus `manifest.json`).
Any implementation of the NIDO agent protocol can be tested against them
without knowing TypeScript, by speaking NDJSON over stdio.

## Protocol

The implementation under test (IUT) is started as a child process:

```
<iut-command>
```

It must then, until stdin reaches EOF:

1. read **one JSON object per line** from stdin — each line is one official vector
   (the full vector object: `{id, title, category, kind, input?, input_raw?, expected}`),
2. for each vector, compute the normalized result for `vector.kind`
   (same normalization the reference adapter produces — see
   `../reference-ts/adapter.ts` for the exact result shapes),
3. write **one JSON object per line** to stdout:
   `{"id": "<vector id>", "result": <normalized result>}`.

The harness compares `result` with the vector's `expected` using JSON deep
equality (object key order is irrelevant). Anything else on stdout breaks the
protocol; use stderr for logs.

`kind` values and their result shapes (v0):

| kind | input | result |
|---|---|---|
| `canonicalization` | `input_raw` (text) | `{ok, canonical?, sha256?, error?}` |
| `signature` | `input {key, message, signature}` | `{ok}` or `{ok:false, error}` |
| `envelope` | `input_raw` (text) + `input.ctx` | `{ok, message_type?, sender_device?, task_id?, error?}` |
| `policy` | `input {rules, request}` | `{ok, decision}` |
| `budget` | `input {state, steps, opts}` | `{ok, remaining?, state?, error?, at_step?}` |
| `disclosure` | `input {value, allowed_paths}` | `{ok, projected}` |
| `graph` | `input {nodes, budget}` | `{ok, total?, error?}` |
| `delegation` | `input {chain, now, pubkeys}` | `{ok, leaf_subject?, max_uses?, error?}` |
| `consent` | `input {grant, request}` | `{ok, uses_left?, error?}` |
| `version` | `input {protocol_version, capability_version}` | `{ok, error?}` |
| `extension` | `input {core, attempts}` | `{ok, results}` |
| `state_machine` | `input {machine, events}` | `{ok, final?, error?, at_event?}` |
| `idempotency` | `input {task_ids}` | `{ok, log, duplicates_rejected, executed_count}` |

## Running

```
python3 runner.py --impl ./my-iut [--vectors ../vectors/v0/final]
```

Exit code 0 iff every vector matches. A results file
`differential-results-<impl>.json` is written for the record.

## Notes

- `expected` values were generated by the TypeScript reference. The harness
  does NOT trust the reference: for a real differential test, the IUT must be
  an independent implementation (different author, ideally different language).
  Disagreements must be investigated as spec ambiguities, not auto-resolved in
  favor of either side.
- `reference-python/` contains a PARTIAL second implementation
  (canonicalization + SHA-256 only), used to differentially test the trickiest
  component. It is not a full second implementation.
