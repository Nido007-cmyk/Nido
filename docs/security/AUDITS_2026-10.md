# Security audits — October 2026

> **Language:** English · [Español](../es/security/AUDITS_2026-10.md)

**What this is:** a public summary of the internal adversarial security
reviews performed on NIDO's P2P protocol stack in October 2026 — what was
reviewed, what was found, what was fixed, and what was explicitly **not**
covered. This is not an external audit. No independent third party has
reviewed this code.

## Rounds

| Round | Date | Scope | Base |
|---|---|---|---|
| Security review | 2026-10-08 | `src/p2p/` (handshake, crypto, transport, negotiation, delegation tokens), `src/agent/delegation/` (executor); plus external research on Bluetooth attacks (2024–2026), capability-token literature, prompt-injection defenses, Android 14/15 foreground-service rules | handshake HELLO v3 + CONFIRM v1, delegation v1 |
| Red-team round 1 | 2026-10-08 | Same code scope + native Kotlin module; adversarial review with attacker mindset | 7 hardening commits on top of `0d9f4de` |
| Red-team round 2 | 2026-10-08 | Attacked the round-1 *fixes themselves*; new surface (Kotlin native layer, reconnect manager, QR ceremony, backup/restore, model prompt construction) | 13 security commits on top of `0d9f4de` |

**Methodology:** read-only adversarial code review. For each area the reviewer
enumerated realistic attacker capabilities first (paired malicious peer,
nearby unpaired attacker, on-device malware, passive observer), then
attempted to break the control under those preconditions. Findings are rated
by realistic exploitability, not theoretical worst cases. Severity was not
inflated: several investigated angles were reported as "checked and found
clean".

## Findings and fixes

All actionable findings were fixed and are covered by automated tests.
(Commit SHAs refer to this repository's `main` branch.)

**Hardening (from the security review):**

| Change | Commit |
|---|---|
| Session KDF: raw SHA-512 truncation → HKDF-SHA512 (RFC 5869) | `efc4b94` |
| Ephemeral secrets zeroed on all handshake exit paths | `efc4b94`, `c95f981` |
| Delegation tokens bound to the transport session (cross-session replay killed) | `70c7710` |
| `attenuateToken` verifies the chain before extending it | `70c7710` |
| ApprovalGate: human approval bound to the exact bytes shown (timeout = deny, single consume) | `c287f5b` |
| Spotlighting reframed as a cost-raising measure, not a security boundary; attacker-controlled channels split for per-channel inspection | `d7ca91e` |
| Minimum Android security patch level 2025-03-05 documented (below-app-layer Bluetooth RCE class) | `9d42809` |

**Red-team round 1** — 9 findings (1 HIGH, 4 MEDIUM, 4 LOW):

| Finding | Severity | Status |
|---|---|---|
| Peer memory poisoning via `task:remember` (persistent indirect prompt injection into the owner's agent context) | HIGH | Fixed — peer facts namespaced out of owner context; dedup scoped by source (`3a4aeb0`) |
| Negotiation proposal swap (re-PROPOSE same ID with escalated scopes) | MEDIUM | Fixed — duplicate-ID PROPOSEs rejected fail-closed (`5d934e1`) |
| Negotiation signatures verified against self-claimed key | MEDIUM | Fixed — pinned to QR-established identity (`5d934e1`) |
| Approval card blind to the attached document payload | MEDIUM | Fixed — document hash/size/preview shown, marked untrusted (`2600c98`) |
| Approval TOCTOU + unbounded pending approvals (memory-exhaustion DoS) | MEDIUM | Fixed — liveness re-checked at approve, per-peer cap enforced (`2600c98`) |
| Spotlight delimiter breakout in peer text | LOW | Fixed — delimiters defanged (`12414ae`) |
| Ephemeral secret surviving handshake failure paths | LOW | Fixed — zeroed on all exit paths; synchronous pending reservation (`c95f981`) |
| Pre-authentication resource exhaustion on inbound handshakes | LOW | Fixed — per-MAC rate limit before crypto (`48e2d29`) |
| Static Bluetooth fingerprint (service name/UUID) | LOW | Recorded as a product decision for the privacy review (no code change) |

**Red-team round 2** — attacked the round-1 fixes; 7 of 8 held:

| Finding | Severity | Status |
|---|---|---|
| Round-1 duplicate-ID rejection bypassed via concurrent same-ID PROPOSEs (check-then-set race across two `await` points) | MEDIUM | Fixed — synchronous ID reservation before the first await (`307c165`) |
| `remember_fact` tool bypassing the memory trust boundary (stamps everything `source='user'` with no provenance check) | MEDIUM | Fixed — human confirmation required when tool context contains untrusted content; fail-closed without a confirmation UI (`9f4f48a`) |
| Unbounded negotiation-session growth when the UI tab is closed | LOW | Documented; fix direction recorded |
| Backup manifest checksum never verified on restore | LOW | Documented; fix direction recorded |
| Paired-peer reconnect churn (battery nuisance) | LOW | Documented; fix direction recorded |

## Verified holding

Attacked directly in round 2 and not broken: handshake MITM resistance
(pinned HELLO signatures, dual-nonce CONFIRM, atomic nonce claim, hard
version cut, reflection blocked); HKDF-SHA512 construction and domain
separation; delegation token chain integrity; ApprovalGate core mechanics;
frame-layer length checks with auth-before-parse; sender/recipient binding;
persistent anti-replay; fail-closed posture on every P2P error path;
executor scope firewall; QR pairing ceremony (v1 QRs fail closed).

## Explicitly NOT covered

- **No external cryptographic audit.** These reviews were internal
  code-reading plus literature comparison. The handshake, KDF, and token
  design deserve review by an independent cryptographer before any
  "audited" claim is made — and no such claim is made here.
- **No physical two-device testing.** The approval flow, byte fidelity,
  and concurrency findings were verified in unit/integration tests, not
  on real hardware with two tablets.
- **No adaptive prompt-injection testing against the on-device model.**
  Literature figures concern frontier models; the 0.5B model's actual
  susceptibility is untested.
- **No memory-forensics verification** that zeroed secrets are
  unrecoverable, and no side-channel analysis.
- The delegation feature itself ships **flag-OFF**; its hardened paths
  have no live handler yet.
