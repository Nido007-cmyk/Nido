## VERDICT: DO NOT SHIP

The 6 fixes were attempted in good faith. Three verify fully correct (CR3-NEW, CR3-NEW2, RESTORE-BIOMETRIC).
Three are incomplete or regressive:

- **G4-REGRESSION (CRITICAL, NEW):** the G4 sender-verification fix **breaks TASK_CANCEL for in-flight tasks**.
  `approveTask` deletes the `inboundIndex` entry on approval (`delegationService.ts:450`), so when
  TASK_CANCEL arrives for a running task, the ownership lookup finds nothing and the message is
  dropped — `running.abort()` is never called. The abort path the fix was meant to protect is dead.
- **H2-RESIDUAL (HIGH, NEW):** the H2-NEW "aborted" code chain only works when the abort lands
  *before* `checkBudget()`. An abort arriving *during* `await modelInvoke()` (the dominant case —
  inference takes seconds) is never re-checked; the model runs to completion, `execute()` returns
  `{ok:true}`, and TASK_RESULT is still sent after cancel.
- **K2-TYPEFAIL (MEDIUM, NEW):** the K2-FAILOPEN fix checks `!manifest.sha256` but not its type.
  A non-string truthy `sha256` (e.g. number) passes the check, then `.toLowerCase()` throws,
  the outer `catch {}` swallows it, and the integrity check is skipped entirely — fail-open.

TEST-GAPS from audit #5 persists: zero tests for staging/recovery, abort suppression, or G4 spoofing.

## 1. Fix verification

### 1. CR3-NEW (probe-open before keystore write) — ✅ CORRECT

`src/security/keyRotation.ts:126-164`. `checkStaleRekeyStaging(stagingPath, storeDek, openDb)` now:
1. Reads staging, validates `newDekHex` is a string (corrupt → delete, `recovered:false`).
2. **Probe-opens the DB with the staged DEK** (`openDb(dbPath, newDekHex)` + `SELECT 1`).
3. Probe fails → crash was *before* rekey → deletes staging, **does not touch keystore** (`:157-160`).
4. Probe succeeds → rekey happened → writes to keystore, deletes staging (`:163-165`).

Edge cases checked:
- `dbPath` undefined (old staging format): `openDb(undefined, ...)` throws → catch → delete staging, keystore untouched. Fail-safe direction. ✅
- `storeDek` throws during recovery: outer catch returns `{recovered:false}`, staging **not** deleted → retried next boot. Correct. ✅
- Probe DB is closed in `finally`. ✅

### 2. CR3-NEW2 (staging deleted on revert path) — ✅ CORRECT

`src/security/keyRotation.ts:101-107`. If `storeDek` throws, the code reverts with
`PRAGMA rekey` back to the old DEK **and now deletes the staging file** before returning
`{ok:false}`. Without this, a later `checkStaleRekeyStaging` would write the staged (new) DEK
to the keystore while the DB holds the old DEK → brick. Closed. ✅

### 3. H2-NEW/G5 ("aborted" code preservation) — ⚠️ PARTIALLY CORRECT

The code chain is intact and correct as far as it goes:
- `executor.ts:130` — `checkBudget()` throws `"task aborted by peer (TASK_CANCEL)"` when `aborted` flag is set.
- `executor.ts:206-211` — catch converts it to `{code:"aborted"}` instead of folding into `"executor_error"`. ✅
- `delegationService.ts:480-496` — `approveTask` checks `!result.ok && result.error?.code === "aborted"` → audits `state:"aborted"` → `return false` without sending TASK_RESULT. ✅

**But the residual gap (H2-RESIDUAL, HIGH):** `checkBudget()` is called once per handler,
*before* `await this.config.modelInvoke(prompt)` (`executor.ts:220,230,264`). Trace the
dominant case:
1. `answer()` calls `checkBudget()` (not aborted) → starts `await modelInvoke(prompt)` (seconds).
2. TASK_CANCEL arrives → `running.abort()` → `aborted = true`.
3. `modelInvoke` completes → `finish(true, ...)` → `execute()` returns `{ok:true}`.
4. `approveTask`: `!result.ok` is false → skips the abort branch → **TASK_RESULT is sent**.

The `aborted` flag is `private` with no getter, so `approveTask` cannot detect this either.
Fix: add public `isAborted()` to `DelegatedExecutor` and check `executor.isAborted()` after
`execute()` returns, regardless of `result.ok`.

### 4. G4 (sender verification on TASK_CANCEL/RESULT/REJECT) — ❌ REGRESSION (CRITICAL)

**G4-REGRESSION:** the fix breaks legitimate TASK_CANCEL for approved, in-flight tasks.

Data flow:
1. `handleTaskRequest` → `inboundIndex.set(requestId, {taskId, peerPkHex, ...})` (`:407`).
2. User approves → `approveTask` → `inboundIndex.delete(requestId)` (`:450`) → executor starts → `runningExecutors.set(taskId, executor)` (`:467`).
3. Peer sends TASK_CANCEL → new G4 code loops `inboundIndex` for `taskId` (`:288-293`) → **not found** (deleted in step 2) → `if (!ownerPeerPk) return;` (`:294`) → **dropped**.
4. `running.abort()` (`:305-308`) is never reached.

The pre-G4 code handled this correctly (went straight to `runningExecutors.get()`).
The existing test (`delegationService.test.ts:245-260`) only covers the pre-approval case
(manually inserts into `inboundIndex`, never goes through `approveTask`), so it passes while
the real flow is broken.

The RESULT/REJECT half of G4 is correct: `tracked.peerPkHex === fromPkHex` check (`:315-318`)
uses the `outbound` map which persists until the response arrives. ✅

The TASK_CANCEL half needs a peer-ownership record for *running* tasks. `runningExecutors`
stores only the executor (whose `peerPkShort` is truncated to 16 chars — unusable for
verification). Fix: maintain `runningPeers: Map<taskId, peerPkHex>`, set alongside
`runningExecutors.set` in `approveTask`, delete in the `finally`, and consult it in the
G4 check when `inboundIndex` has no entry.

### 5. K2-FAILOPEN (fail-closed on missing SHA) — ⚠️ INCOMPLETE

`src/security/backup.ts:257-268`. `if (!manifest.sha256) return {valid:false}` correctly
rejects null/missing/empty SHA. ✅

**But K2-TYPEFAIL (MEDIUM, NEW):** no type check. If `manifest.sha256` is a truthy non-string
(e.g. `123` from a hand-crafted manifest):
- Line 260: `!manifest.sha256` is false → passes the fail-closed gate.
- Line 267: `manifest.sha256.toLowerCase()` throws TypeError.
- Line 284: outer `catch {}` swallows it → comment says "Sin manifest, continuar con validación básica" → **the backup is accepted with no integrity check**. Fail-open.

Note `validateBundle` (the `.nidobackup.json` path) does this correctly:
`typeof m.sha256 !== "string"` (`:196`). The raw-.db path must match:
```ts
if (typeof manifest.sha256 !== "string" || !manifest.sha256) { return {valid:false, ...}; }
```
Same latent pattern for `manifest.dekFingerprint.toLowerCase()` (`:273`) — a non-string
truthy fingerprint would skip K1 silently. Lower severity (K1 is already soft), fix with the
same typeof guard.

### 6. RESTORE-BIOMETRIC (biometric gate on restore) — ✅ CORRECT

`src/ui/ModelSetupScreen.tsx:496-500`. `requireUnlock("Restaurar backup")` runs before
`restoreBackup(uri)`; cancel/throw → caught → error alert, no restore. Verified
`restoreBackup` has exactly **one** caller in src (`ModelSetupScreen.tsx:501`) — no bypass path. ✅
